# Releasing

[English](RELEASING.md) · [简体中文](zh-CN/RELEASING.md)

`package.json` is the only version source. `src/version.ts` is generated by
`scripts/sync-version.mjs`; do not edit it by hand. `npm run check` fails when the two files diverge.

## Preflight

```sh
npm ci
npx playwright-core install --with-deps chromium
npm run check
npm run lint
npm run format:check
npm run test:coverage
npm run smoke:install
```

`smoke:install` builds, packs, installs the tarball into a clean temporary project, imports the SDK and
runs `tuilens --version`. The local coverage gate is 70% lines, 65% branches and 70% functions.

## Version and tag

1. Bump `version` in `package.json`.
2. Run `npm run version:sync`.
3. Update `CHANGELOG.md` and the roadmap.
4. Run the preflight above and commit the release.
5. Create and push an annotated tag matching the package version, for example `v0.5.5`.

The tag triggers `.github/workflows/release.yml`. It repeats the quality gates, runs the clean-install
smoke, verifies `GITHUB_REF_NAME === v${package.version}`, publishes with npm provenance and creates a
GitHub Release from generated notes.

## Repository secret

Set an `NPM_TOKEN` Actions secret with publish rights for the `tuilens` package. The release job needs
`contents: write` and `id-token: write`; both are declared in the workflow.
`publishConfig.registry` is pinned to `https://registry.npmjs.org/`, so a maintainer's local mirror
configuration cannot redirect a real publish.

## Dependency policy

Stable dependencies use caret ranges. `node-pty` is the only exact pin because current releases are
prereleases. Track it with:

```sh
npm view node-pty dist-tags --json
```

The scheduled soak workflow archives this output and `npm outdated --json` for review. Dependabot covers
stable npm and GitHub Actions updates.

With npm 12+, consuming projects must allow `node-pty`'s native install script in their root
`package.json#allowScripts`. The clean-install smoke exercises that consumer shape.
